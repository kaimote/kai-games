how the bubble graph works

Companion to the editor. One JSON file: no database, no account, no request after load.

{
  "version": 1,
  "name": "my structure",
  "nodes": [
    { "id": "a", "label": "a", "notes": "", "r": 34,
      "color": "#5fe3a1", "pos": [-52, 14, -10] }
  ],
  "edges": [
    { "a": "a", "b": "b", "kind": "link" }
  ]
}

Four relationships, two places

Two of them are not stored at all. Encapsulation and partial overlap are recomputed from radii and positions every frame, because position is the claim. Store containment and it can disagree with the picture the moment a bubble is dragged; derive it and it cannot.

encapsulated
dist(a,b) + r_small ≤ r_big, parent = the smallest sphere that still encloses. A parent is always strictly larger, so the parent chain strictly increases in radius and cannot cycle — that is the whole cycle-proof, no guard needed.
overlapping
dist(a,b) < r_a + r_b for a pair that is not nested. Drawn as the circle where the two shells meet.
linked
an edges entry, kind: "link". A spring resting at 1.14 × (r_a + r_b): touching, not merged.
gravitationally pulled
an edges entry, kind: "gravity". Same spring, rest length 3.4 × (r_a + r_b), softer. Disconnected in the data, nearby on screen — which is exactly the difference: a link is a relationship, gravity is only an adjacency you asked for.

Anything with no edge and no enclosure is free-floating. Origin gravity is a boundary with a dead zone, not a field: inside it the force is exactly zero, so a relaxed graph stays relaxed instead of convecting forever.

Why the layout stops

Force-directed layouts that terminate do so by cooling, not by damping. A monotone scalar (alpha) scales every force and reaches zero in a fixed number of steps, so "done" is a property of the schedule rather than a race against a threshold. Tuning damping alone does not fix it: the slowest mode of a coupled spring system is arbitrarily slow, and a damped version of this editor decayed to a floor and then crept for minutes without landing.

A step is the unit of time. Driving the schedule from elapsed wall time makes convergence speed a function of frame rate — measured, 36 seconds at 8 fps for a 7-bubble graph.

Your file, and nothing else

The graph lives in the tab. Export gives you a .json you own; Import, dragging a file onto the page, or pasting json loads one back. There is no server component and no browser-side store, so nothing about your structure outlives the tab unless you take the file. That is the whole storage model, and it is deliberate: a tool that stores nobody's structure has no structure to leak, and nothing to migrate later.

Running it locally: python3 server.py in the project folder serves the same static files over a real origin and prints the address. That server is read-only — it cannot write anything, because the editor no longer asks it to.
